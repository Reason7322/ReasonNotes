# KDE Connect Feasibility Report — Physical Test Pending

## Current result

The data-safety synchronization core and both platform adapters are implemented and pass non-live verification. A KDE Connect recommendation is intentionally withheld until the physical POCO procedure establishes actual Android intent routing, folder discovery, interaction cost, and bidirectional convergence.

## Verified strengths

- Immutable readable Markdown revisions protect every competing edit and deletion.
- Keep Linux and Keep Android create deterministic multi-parent resolutions; Skip makes no change.
- Duplicate, renamed, out-of-order, stale-resolution, and interrupted generated-state scenarios are safe in automated tests.
- A bounded delivery ledger avoids indefinite automatic resend while retaining every revision in history.
- Linux has a scan-before-send adapter; Android has a user-initiated scan-before-send probe with persisted SAF and temporary content-URI permissions.

## Remaining risks

- The Android `deviceId` route may not identify the Linux peer as expected on the installed KDE Connect version.
- KDE Connect may foreground an activity or chooser often enough to make the workflow awkward.
- KDE Connect has no ReasonNotes import acknowledgement; physical use may show that receipt/inventory envelopes are necessary.
- OEM storage/lifecycle behavior and interrupted incoming transfers remain unobserved.

## Recommendation gate

- Recommend **KDE Connect** only if P2–P6 pass with acceptable interaction and exact convergence evidence.
- Recommend **Syncthing** if reliable dedicated-folder mirroring is available and a companion app is acceptable.
- Recommend a **small built-in LAN protocol** if direct targeting is unstable, repeated chooser interaction is required, or trustworthy receipt acknowledgement is necessary.

The Milestone 2 plan will be written after this gate. No Flutter decision has been made.
